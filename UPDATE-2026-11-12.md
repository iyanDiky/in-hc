# Penyesuaian persuratan — 12 November 2026

## Nomor surat masuk dan keluar

- Surat masuk melanjutkan nomor dari baris logbook aktif terakhir pada tahun yang dipilih dan nomor input baru aktif. Nomor besar pada siklus lama hasil impor tidak lagi menyebabkan loncatan urutan.
- Surat keluar melanjutkan nomor aktif terbesar pada tahun tanggal surat. Arsip tanpa tanggal memakai `tahun_arsip`.
- Jika nomor terakhir dihapus, nomor tersebut boleh dipakai kembali. Contoh: nomor aktif terakhir 163, tambah mendapat 164, hapus 164, tambah lagi mendapat 164. Menghapus nomor di tengah tidak mengisi celah otomatis.
- Tahun yang belum memiliki data dimulai dari 1. Surat masuk, surat keluar, dan lamaran memiliki urutan terpisah. Aturan lamaran tetap memperhitungkan soft-delete.
- Create memakai transaksi dan advisory lock PostgreSQL per jenis register/tahun untuk menjaga urutan pada permintaan bersamaan.

## Form tambah surat keluar

- Kolom nomor surat tampil saat tambah maupun edit.
- Saat form tambah dibuka, nomor berikutnya terisi otomatis berdasarkan tahun tanggal surat.
- Nomor dapat diedit untuk surat bertanggal lampau. Nomor manual disimpan sesuai input; perubahan tanggal tidak menimpa nomor yang sudah diedit manual.
- Selama nomor belum diedit, mengganti tanggal memperbarui saran nomor. Respons API lama tidak menimpa input terbaru.
- Create menolak nomor yang masih aktif pada tahun yang sama, termasuk arsip tanpa tanggal. Nomor dari tahun lain atau nomor yang telah dihapus boleh dipakai. Klien API yang tidak mengirim nomor tetap mendapat nomor otomatis.
- Tanggal awal form mengikuti tanggal lokal perangkat.

## Dukungan data dan deployment

Perubahan ini juga membawa dependensi lokal yang belum ada di GitHub: kolom metadata sumber dan tanda pemeriksaan impor, catatan panjang, tahun arsip serta tanggal kosong surat keluar. UI menampilkan badge **Perlu cek** dan pencarian catatan; surat masuk diurutkan menurut tanggal lalu nomor numerik agar urutan stabil.

Migrasi hanya menyesuaikan skema, tidak menghapus atau mengimpor ulang data transaksi. Database dan lampiran tetap dikelola terpisah dari Git; pull di Mac tidak menyalin data dari PC Windows.

Windows dapat menjalankan `powershell -ExecutionPolicy Bypass -File .\scripts\start-lan.ps1`. macOS/Linux tetap memakai `sh scripts/start-lan.sh`. Startup menjalankan migrasi, cache Laravel, dan build frontend. Port aplikasi LAN tetap 5173; PostgreSQL lokal memakai port loopback 5433. Backup tidak disertakan dalam Git atau konteks build Docker.

## Validasi

- Tujuh tes surat keluar: nomor manual bertanggal lampau, duplikat aktif, pemakaian nomor lintas tahun/setelah dihapus, hapus nomor terakhir/tengah, reset tahun, dan arsip tanpa tanggal.
- Lima tes fitur institusi pendidikan untuk memastikan integrasi lamaran tetap berjalan.
- Regresi surat masuk diuji pada salinan database: urutan aktif, hapus lalu input ulang, counter lama tidak menyebabkan loncatan, dan reset tahun baru.
- Build frontend production serta HTTP halaman LAN berhasil. Interaksi visual form belum diuji dengan browser otomatis.

Jalankan tes fitur tanpa menyentuh database aplikasi:

```sh
docker compose exec -T backend php artisan test --filter='OutgoingNumberTest|InstitusiPendidikanTest'
```

Tes fitur tersebut memakai database SQLite in-memory terpisah.
